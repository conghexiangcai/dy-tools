# 抖音整理箱 2.4.1 验证说明

日期：2026-10-18（北京时间）。

## 修复范围

- 关注管理的本人信息、关注分页、主页详情和视频时间请求遇空响应时，保留断点，按 30、60、120、300 秒递增等待，之后每 300 秒自动重试；成功后继续原请求，每个请求独立计算重试次数。
- HTTP 429 遵守更长的服务端 `Retry-After`。限流时只检查现有页面是否有验证码，不提前刷新网页；等待结束后核验当前账号再重试。
- 已知空数据包括空白正文、非 JSON 页面、JSON null／空对象／空数组、空关注分页和 null 主页详情。关注空末页与本人总数冲突时不直接保存为空名单；重新核验当前总数，真正的零关注仍可完成。
- 倒计时独立于验证码等待，支持暂停、重启后继续。每秒仅更新任务提示，不每秒重载全部关注数据。
- 普通网络错误继续最多额外重试两次；验证码、登录失效、账号切换、身份或结构异常不进入无限重试。已知的账号不可用作品响应继续保存为未知，不冒充零，也不阻塞整批。

## 验证边界与升级

本次通过可重复的合成响应验证等待和续采，没有主动请求真实账号来触发平台限制，也不能保证平台在某次等待后一定恢复。持续空响应会继续等待，可随时暂停；需要人工处理的验证码和失效登录仍须处理。

本次不更改粉丝团、群成员、批量写入及作品下载任务的重试规则。Windows 版原有功能和限制沿用 2.4.0；安卓和 iOS 不在本次交付范围内。

退出旧版，将新版解压到独立目录，再启动“抖音整理箱.exe”。继续使用原 `DouyinFollowingReview` 数据目录，无需重新导入；旧任务点击“继续”即可恢复。新版本不自动启动历史任务。发行包只包含软件、源码和说明，不包含测试数据库、会话或认证。


使用旧版可能受平台接口变化影响；优先使用 2.4.3。未留存完整 ZIP 的中间构建仅提供源码，不以新版二进制冒充。
