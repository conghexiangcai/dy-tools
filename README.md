# 抖音整理箱

Windows 10 / 11，64 位免安装软件。解压完整文件夹，双击 **抖音整理箱.exe**。无需安装 Python、Node，也无需聊天助手保持运行。

2.3.1 修复群扫描、登录状态同步和分组独立刷新。2.3.0 新增“分组管家”“关注动态”“群成员变动”三个入口。原粉丝团打卡、指定时间点和服务器脚本继续保留。升级先退出旧版，解压新版到独立目录后启动；本机数据目录仍为 `DouyinFollowingReview`，不自动清空关注名单、勾选、打开记录或忽视名单。新版仅增量增加记录表，全新电脑仍从空名单开始。

## 2.3.1 修复说明

- 所有软件窗口和只读核查窗口统一拦截唤起客户端的跳转，包括 `bytedance:`、`snssdk1128:` 及未知外部协议；正常抖音网页仍在软件内打开，不需要安装抖音 App。
- 群成员扫描使用完整 IM 群对象；网页刷新或重启后恢复群资料，再从原成员游标继续。组件尚未初始化时先等待，失败会显示群名、分页位置和具体原因。已读成员保留，不完整扫描不会生成确定的减少结论。
- 工具箱与所有功能页共用在线登录状态。已核验时显示“查看登录账号”和昵称；旧缓存 UID 不冒充已登录。登录完成返回软件会自动核验，失效时提示重新登录。
- 分组管家可直接“刷新全部分组”，无需先采集关注名单。失败保留上次完整结果。
- 首次关注名单正在分页时显示已获取人数，完整后才切换展示；已有完整名单继续保留。
- 上次群扫描失败可点击“继续扫描”恢复；若人数发生变化导致不完整，再勾选该群重新扫描，不清空历史。

## 分组管家

1. 从工具箱进入“分组管家”，登录并连接当前账号，点击“刷新全部分组”。这里读取的是抖音关注分组，不是聊天群或本地标签；无需重新获取每个人的作品详情。
2. 左侧选择分组，右侧可以按昵称、抖音号或 UID 搜索。支持勾选当前页、勾选全部筛选结果和跨页保留。原关注管理的“已勾选账号加入分组”“筛选结果加入分组”会将固定名单带入此页，不清空原勾选。
3. 选择操作及目标分组，点击“生成分组操作预览”，核对账号、来源、目标和人数，再确认执行。加入可选多个目标；复制保留来源；移动先确认加入目标，再移出指定来源，保留其他分组；移出只改变分组归属，不取关。
4. 每人执行前读取最新归属，提交后回读。超时结果不明时暂停，继续前先核对；已是目标状态的跳过，不重复提交。手机端新增的其他归属保留。分组删除或成员资料过期时暂停，重新刷新再创建预览。
5. 下方“分组操作记录”可重新打开任务，暂停、继续或处理验证码；验证完成确认后等待 5 秒。关闭软件后不会自动执行；重启选择原任务，核对后继续。
6. “忽视所选成员”只本地隐藏；“预览取关所选成员”进入原批量取关确认流程；支持 JSON／Excel 导出所选成员。分组标题的人数来自抖音，可能包含已忽视账号；右侧默认排除忽视账号，避免误操作。分组读取失败时保留缓存并禁止全组操作。

**当前限制**：新建、改名、删除只有 APK 静态接口定义，未用测试账号完成真实提交和回读，本版按钮明确禁用，请暂时在抖音中操作。现有分组成员设置接口沿用旧版已核查通路；新增的批量队列仅使用合成数据测试，本次没有修改你的真实分组或关注关系。

## 关注动态

1. 进入“关注动态”，选择“我的关注”或“我的粉丝”，点击“刷新当前名单并比较”。本功能只读取成员名单，不逐人重采作品、粉丝团或主页指标，也不替换关注管理页的详情快照。
2. 每类首次完整读取只建立基准，不将所有账号标成新增。之后每次完整刷新自动与上一份完整名单比较；已有完整且人数相符的关注历史也会显示。人数不符、分页受限、网络失败或缺失信息保存为不完整，不生成确定的减少记录。
3. “变化记录”可选择历史比较；可按后次采集日期、变化类型和昵称／抖音号／UID 过滤结果。展开“选择两个历史版本比较”可手动指定前后版本；必须同一账号、同一名单且时间先后正确。
4. “我的关注”和“我的粉丝”分别保存任务断点。在相应页签点“继续读取”；验证码需点击“已完成验证，等待 5 秒”。切换账号或网络异常会暂停，旧响应不会进入新账号的结果。
5. 导出 JSON／Excel 包含本次完整比较、前后快照 ID、时间、完整性和账号范围。页面的关键词／类型只过滤展示，“导出本次完整比较”导出这一对版本的全部变化；ID 按文本写入 Excel。

变化来自两次名单，不代表准确的关注／取关时刻，不判断减少是主动取关、删除、封禁或其他原因。忽视名单、本地取关隐藏及页面筛选不影响原始名单比较。只有软件逐项执行并回读确认的对应操作，才额外注明“由本软件操作”。

**粉丝读取仍待实测**：本次真实登录核查未能执行，粉丝列表保持只读核查入口。软件会核对返回字段、登录身份、分页推进和最终人数，全部通过后才保存为完整；不保证当前抖音网页登录态能够读取全部粉丝，不能用粉丝总数替代实际名单。

## 群成员变动

1. 进入“群成员变动”，点击“读取已加入群目录”，手动勾选普通群或粉丝群。所有群默认不勾选，只扫描你勾选的群。
2. 点击“扫描勾选群并比较”，读取成员时复用原群成员检索接口，不读取聊天消息正文。首次扫描建基准，后续每个群独立与上一次完整扫描比较。
3. 在“群”下拉框选择一个群，查看新增、减少及可核对的昵称／群昵称变化。只有两次都有有效名称且名称不同时才记资料变化，缺失名称不当作改名。同名不同 UID 不会合并。
4. 扫描中断、权限不足、成员人数冲突的名单标为不完整，不将没读取到的人视为已离开。群从目录中消失也不会产生全员退出。暂停、继续、重启恢复和验证码操作沿用群成员检索流程。
5. 如需导入名单，点击“打开群成员检索 / 导入”。导入快照独立保存，可回到此页手动选择同群前后版本比较，不会替换在线扫描的自动基准。同一个群的历史版本不会被当成多个群。
6. 支持 JSON／Excel 导出本次完整比较。群成员加入／减少只表示两次读取范围内的变化，不推断主动退群、被移出及准确时间。

这三个模块本版均为手动刷新，不创建定时监控任务。开发测试使用独立合成数据库，不会清理你的真实数据。验证范围详见同目录“验证说明.md”。

## 粉丝团打卡

1. 进入“粉丝团打卡”，登录并连接当前账号，点“刷新名单与状态”。范围为全部已加入粉丝团，不按灯牌是否点亮过滤；刷新只读取。
2. 点“立即签到”提交普通当日签到，已成功的跳过。需要额外入圈、业务类型不明或信息缺失的单独显示；不送礼、不补签、不自动入圈。超时先回读，不能确认则保留未知。
3. 支持暂停、继续／重试、状态筛选和导出 JSON。新一轮刷新全部名单；断点恢复先核对未确认项，跨日重开。数据独立保存在 `checkin.sqlite`，不覆盖原使用记录。
4. 时间默认选择**指定多个时间点**，如 `08:30,12:00,21:15`；也可改为起始时间、次数、间隔。北京时间、自动排序去重，页面预览执行时刻。
5. **定时默认关闭**。勾选启用并保存才创建 Windows 任务，电脑需开机且登录 Windows。任务名 `DouyinToolboxCheckin-登录UID`；移走软件后须在新位置重新保存。取消勾选并保存会删除对应任务。发生验证／失效／限流暂停后，定时保持等待人工继续。
6. 验证码在抖音窗口人工处理，点击“已完成验证”，等五秒后核对；普通继续不能跳过等待。其他工具正在工作时不会抢占批量任务；打卡结束后采集由你手动恢复。
7. 默认复用软件登录。“导入／替换认证”只接受同一 UID，Windows 加密保存。到期重新登录或替换，记录保留。服务器用“导出服务器认证”生成的 `credentials.json`；含登录 Cookie，只放在自己的设备。服务器包内说明包含常驻、指定时间、断点及认证更新步骤。

已实测 48 个粉丝团和一个无圈子团签到回读；独立 Node 已完成全量只读核查，真实服务器 POST 尚未单独实测。详细边界见验证说明。本次未启用定时、未批量签到。

## 新工具使用

- **关注管理**：设置筛选后点“取关当前筛选的全部账号”，会生成所有分页匹配账号的固定预览；“取关所选分组全部账号”使用所选具体分组全部已同步成员，忽略粉丝、作品等其他筛选。分组读取失败时需先刷新分组。两种模式都排除忽视名单。
- **忽视名单**：每行“忽视”或“忽视已勾选账号”只在本地隐藏账号；不取关、不拉黑，也不清除勾选和打开记录。到“忽视名单”恢复后仍沿用原记录。
- **关注迁移**：原账号完整同步关注名单后，保存当前名单；此快照包含被忽视的关注账号。切换抖音账号，点击“连接当前账号”，然后从保存的迁移清单生成预览。拒绝迁移到原账号，已关注的人自动跳过；原账号的关注不改变。
- **点赞清理／收藏整理／推荐清理**：先完整读取当前账号作品列表，再生成固定预览；读取中断不提供不完整的可执行名单，可停止后重读。收藏整理只覆盖收藏的视频和图文作品，不包括音乐、合集等其他收藏类型。推荐清理是撤销主动推荐过的作品，不是重置推荐流。
- **执行预览**：点击“确认并执行”后还会显示原生确认窗口，标明登录 UID、范围、总数和剩余数；取消确认不提交。每项提交前检查身份和当前状态，提交后回读，空响应／超时不当作成功。写入不盲目重试，结果未知立即暂停，下次继续先读取结果。
- **暂停、重启和验证码**：逐项保存断点，关闭后不会自动执行。账号切换暂停旧任务。出现验证码后人工处理，在执行预览点“已完成验证”，等待 5 秒检查后继续。队列单并发，每个网络请求至少间隔 1 秒、项目间隔 1.5 秒。开始执行前会暂停其他采集或查询；结束后需自行恢复。
- **推荐清理速度**：尚未确定所有推荐状态枚举，暂用本人推荐列表的实际成员关系核对每项。列表很长时回读较慢；失败保留未知，不猜成“已撤销”。
- **群成员检索**：读取当前登录账号已加入群并勾选扫描，或导入 JSON／Excel 名单，按 UID 多群查重、查找某人、与导入名单比较；详见下节。
- **执行记录**：按登录账号保存预览、逐项状态和断点，可导出 JSON。批量操作不会更改原勾选／打开记录；已回读确认取关的账号在旧快照中隐藏，历史保留。

这些批量整理功能使用合成数据测试，**未对现有真实账号执行取关、关注迁移、清理点赞、收藏或推荐**。新增接口按抖音网页请求代码接入，真实写入仍需指定测试账号实测；接口受限、作品删除或私密关注待审核等不明确状态会暂停，不会伪报完成。

## 群成员检索与分享链接

1. 从工具箱进入 **群成员检索**，登录并连接账号，点击 **读取全部已加入群**。如果提示 IM 未就绪，在抖音窗口点击顶部“消息”，待组件加载后重试，不必进入具体聊天。
2. 群默认不勾选。手动选择需要的群，点 **扫描勾选群**；结果逐页保存。支持暂停、继续、关闭后续传。验证码人工处理后点 **已完成验证**，等待 5 秒检查后继续。启动前暂停其他采集任务，结束后由你手动恢复。
3. 成员快照表 **A 区**用于多群查重和查找某人。查重至少选两个不同群；同一群多份历史记录只使用所选的最新一份。UID 相同才合并，同名不同人分开。
4. **名单比较**：A 区选择导入名单，B 区选择待比较的群快照；两边分别合并成员后显示共同成员、仅导入存在、仅所选群存在，保留各人的群归属。任意一边不完整，差异仅表示“本次已读取范围内”。
5. **查找某人**：支持抖音号搜索、作品／主页完整分享文案、官方链接、sec_uid 和明确选择的内部 UID。作品识别作者，资料卡标明来源和私密状态；先核对，再点击查找。昵称关键词只筛选已有结果，不代替身份匹配。
6. **导入 JSON / Excel**：软件导出的文件可直接重新导入。外部 Excel 选择工作表和对应列，至少要有可靠内部 UID；可映射群 ID 列或填写固定群 ID。只有昵称、公式或已丢失精度的长数字 ID 会列入待处理，可另行导出。导入创建独立快照，不覆盖原扫描或旧文件。
7. **导出 A 区成员**导出勾选快照的完整成员；**导出本次完整检索结果**包含结果及参与快照，不受结果搜索框和分页影响。支持 JSON / XLSX；Excel 有“群信息”“成员”表，检索结果另外成表，ID 写为文本。
8. 所有数据按登录 UID 隔离保存。来源时间未知就显示未知；人数冲突、未读完、权限错误不会显示为完整。成员接口没有昵称时显示“未提供昵称”，保留 UID 和 sec_uid，不批量逐人补采主页。

添加主播和识别查询用户同样支持分享作品／主页；可直接粘贴带有 `https\://` 的完整文案。添加主播先展示账号，再点击 **添加该主播**。多个不同链接须只保留目标链接；作品失效或作者不匹配会明确报错。

## 粉丝团查询

1. 在工具箱首页点击 **粉丝团查询**，打开独立工具窗口。复用软件内登录，不需安装抖音客户端或提供 Token。第一次使用可点“登录抖音”，完成后点“连接当前账号”。
2. 左侧添加主播：输入**抖音号**、作品／主页分享文本、完整主页地址或 `sec_uid`。默认数字也按抖音号检索；使用内部 UID 时，请切换输入类型为“内部 UID”。搜索会列出候选昵称和抖音号，核对后点击“添加”，不会自动采用第一条结果；“加载更多结果”读取后续候选。可填写备注、勾选、删除；主播名单首次为空，不自动导入任何个人列表。
3. 输入目标用户，点 **识别账号**；抖音号搜索需先选择正确候选，再核对昵称与主页，点 **查询勾选主播**。只查询本次勾选的主播，不代表该用户加入的全部粉丝团。主播名单或备注后续修改，不改变已经创建的查询范围。
4. 灯牌显示等级、已点亮／未点亮。接口状态 0 在 APK 中表示未知，软件不会把它显示成“未加入”。荣誉等级与灯牌等级分别展示；钻石范围显示为 `下限 ≤ 钻石 < 上限`，来自核实后的接口等级门槛，**不是实际消费账单**，不换算现金。缺失或冲突保持未知。
5. **会员／守护及到期时间暂时显示未知**：已找到 APK 字段和状态枚举，但尚未取得有效会员的线上对照样本。不会把截图的黄色 V 或粉丝团等级冒充会员开通证明。
6. 查询单并发、间隔至少 1 秒；启动前暂停关注采集并保留其断点，之后可回主界面手动继续。网络或空响应最多额外重试两次，等待分别为 2 秒、4 秒；粉丝团单次请求上限 12 秒，失败显示未知，连续三个主播失败暂停。普通失败只检查验证码，不反复重新打开主页；查询时显示当前步骤与已等待秒数。验证码由你处理，点击工具窗口的“已完成验证”后等待 5 秒继续。
7. **暂停／继续** 支持关闭软件后的断点；**重试失败项** 只重试请求失败的项目。接口成功但灯牌未知的账号，需要重新创建查询才能更新。切换账号后主播名单和任务分别保存，旧响应不会写入新账号。
8. **导出结果** 支持可搜索 HTML、JSON 和 Markdown，保留本次主播范围、查询时间、失败说明和估算标识。工具内打开主页不会修改关注清单里的打开记录。

本功能只读，不自动关注、取关、加入粉丝团、开通会员或续费。接口可能变化，软件会显示真实请求失败或待验证状态。

**私密标识**：已明确为私密的账号，在主播列表、搜索候选、用户卡片、结果及导出中显示标识；独立主页窗口在“关注／已关注／互相关注”按钮左侧显示“🔒 私密账号”，切换主页时重新匹配。关注按钮滚出可见区域、出现验证页面或左侧空间不足时隐藏；未知状态不猜测。此前保存的主播若缺少隐私字段，可重新添加同一账号更新资料，原备注和勾选保留。

**速度与空响应**：主页链接／sec_uid 识别改用网页资料接口，单次任务不再额外请求一遍粉丝团资料；相同登录会话的身份校验最多复用 60 秒，每个请求仍检查会话是否变化。2026-10-06 实测搜索首屏约 0.8 秒、下一页约 1.6 秒，单次正样本关系请求约 0.14 秒（仅为样本耗时，并非保证）。同一目标和主播的关系接口仍可能返回 HTTP 200 空内容，根因尚未确认；不能承诺彻底消除。空内容保留为未知，使用“重试失败项”即可，不要将其解释为未加入，也无需因此反复登录。

## 第一次使用

全新数据目录首次启动显示 **0 个账号**，不内置任何个人关注名单或取关历史。已使用过的电脑升级后继续显示本机保存的名单、断点和使用记录，不自动清空。

1. 点击 **登录抖音**，在弹出的抖音窗口手动登录。
2. 回到主界面，进入 **关注管理** 后点击 **连接检查**。软件检查本人身份，从当前账号关注列表选取样本主页核对作品数；没有关注账号时使用本人主页。无需提供 Token。
3. 点击 **更新数据**，获取当前全部关注名单及指标。先完整获取关注列表，再切换页面名单；详情随后逐个更新。每次“更新数据”创建一个新任务。
4. **暂停／继续** 使用本次任务的断点。软件关闭后重新打开也可以继续，已成功获取的账号不会在同一次任务中重复获取。

遇到验证码时软件暂停，并显示实际触发验证的采集窗口。请手动处理，点击窗口或主界面的 **已完成验证**；软件倒计时 5 秒，检查后重试中断的请求。验证仍未解除时继续等待，不会把失败当成 0。普通网络错误最多额外重试两次，然后保存断点并显示原因。空白或非数据响应先检查是否有验证码，没有发现验证时同样有限重试；仍无法读取则打开抖音窗口，保留中断账号等待继续。登录失效时重新登录后点“继续”。

## 筛选与手动查看

- 保留原清单页面：粉丝数、作品数上下限，或／且，互关，是否打开，关键词搜索，关注减粉丝差值排序，以及每页 50 个账号。
- 数值都严格比较；等于阈值不命中。清空表示不限。若要同时限定上下限，选择“且”。私密或缺少可靠计数时作品数为“未知”。
- 已确认私密的账号在昵称后显示 **🔒 私密账号** 标签。隐私状态独立于作品数，保留旧名单中的明确状态；请求失败或隐私状态未知不会误标为私密。HTML、JSON、Markdown 导出均保留标识或字段。
- 最新三条视频的发布时间放在同一列，每条一行；按实际发布时间排序，旧置顶视频不会被误当成最新发布。仅有一两条可见作品时显示实际条数，私密或无法获取时显示未知。
- **最新发布距今大于／小于（天）** 按北京时间自然日严格比较，空白表示不限。这两个时间条件独立生效，再与其他筛选结果取交集；未知时间不会命中。排序菜单可选择距今从近到远或从远到近，未知始终最后。
- 顶部的**预计剩余时长**根据最近请求速度动态计算，不包含暂停和人工验证时间。详情与视频时间各有断点；升级前已经获取的详情会直接复用，随后补齐视频时间。
- 跨页勾选不丢失。每批可选 1、5、10 人，点“打开下一批”在独立主页窗口的标签页中打开；可重开上一批。
- **已请求打开主页不代表已取关**。请在抖音主页手动取关。关注状态来自最近一次名单同步，刷新关注名单后才反映变化。
- 采集窗口和主页窗口独立，共享软件自己的登录状态。采集时请勿在采集窗口切换账号；需要更换账号时先暂停，登录后新建更新任务。
- 更新数据只修改账号指标，不覆盖勾选、筛选条件、打开记录。移出关注名单的账号记录仍保留。

## 抖音关注分组

- 独立主页窗口会在抖音的“关注／已关注／互相关注”按钮正上方显示 **设置分组**，跟随原按钮移动。当前主页不在名单内、按钮不可见或出现验证码时隐藏。
- 点击后读取该账号的真实抖音分组，可多选；点击 **保存** 才提交变更。仅管理已有分组，新建、改名、删除仍在抖音中操作。
- 保存前刷新归属，只提交你勾选产生的增删，保留手机端同时添加的其他归属。提交后回读确认；超时不会自动重发写入，部分成功时展示实际归属，需核对后再保存。
- 切换主页标签、导航或登录账号会取消旧弹窗。网页无法访问本地数据库；分组按钮与弹窗由软件自己的隔离界面绘制。
- “所属分组”在“命中条件”前，已移除“关注状态”展示列。搜索框右侧可按分组筛选，与当前粉丝数、作品数、互关、是否打开等条件叠加；多组账号包含在每个所属分组中。分组成员来自完整分页，尚未进入关注快照的分组成员也纳入指定分组；未核实的作品数仍未知。选择“全部”回到当前关注名单。
- 首次升级自动单独读取分组，不重新采集账号详情；列标题旁的 **刷新** 可独立同步。“更新数据”完整取得新关注名单后也会同步分组。
- “未知”表示尚未完整核实；只有完整读取确认无归属才显示“未分组”。失败保留上次结果并标注未更新。分组缓存按登录账号隔离，HTML、JSON、Markdown 导出均包含分组。
- 不需提供 Token：软件仅在内存中将现有会话用于已核实的抖音服务地址，不导出登录凭据。使用记录导入不改变抖音分组。网页会话失效或服务不再兼容时，会显示实际连接错误。

## 导入旧页面的使用记录

软件不再自动导入历史快照。旧版本已经保存在本机的名单和历史会继续保留；旧浏览器内的勾选和打开记录仍需要由你主动导出：

1. 在原浏览器打开原来的 **筛选名单-v3.html**，自行刷新后，点击左侧 **导出使用记录**。
2. 在桌面软件选择 **导入使用记录**，选择刚保存的 JSON。
3. 软件按当前账号和各被关注账号 UID 合并：已有勾选与打开记录不会清空。属于另一个登录账号的文件会拒绝导入。只有软件尚无使用记录时，才一并采用导入文件的筛选及上一批；只修改过筛选条件也属于已有使用记录。导入期间继续修改筛选或勾选，会保留这些新操作。

我们只给原文件增加导出按钮，不读取或修改旧浏览器的存储。原浏览器若还有未关闭的旧页面，按钮需由你刷新后显示。

## 保存与导出

- **导出名单**：HTML 可独立搜索筛选，JSON 保留完整指标，Markdown 便于阅读。
- **导出使用记录**：单独保存勾选、打开记录及筛选设置，供迁移或备份。
- 软件数据目录：`%APPDATA%\DouyinFollowingReview`。`review.sqlite` 及其 WAL 文件保存任务和记录；`Partitions` 下为软件自己的抖音登录会话。备份整个目录前先退出软件。
- 登录状态只保存在本机，不写入名单、使用记录导出或运行日志。免安装包和源码包不包含登录状态。
- 不同登录 UID 的关注数据与使用记录分别保存。全新安装不预置账号；登录并点击连接检查或更新数据后识别账号。

## 开发和构建（普通使用者不需要）

源码为 Electron + TypeScript + SQLite。SQLite 使用 Electron 内置的 `node:sqlite`，不需要额外数据库服务或原生模块编译。开发环境 Node.js 24，依赖版本锁定在 package-lock.json。

```powershell
npm ci
npm test
npm run smoke
npm run smoke:groups
npm run smoke:fanclub
npm run smoke:tools
npm run package
```

构建产物在 `release`。打包复制完整 Electron Windows 64 位运行时，只有显式列出的代码和空页面模板进入软件与源码包。个人名单、历史备份、开发会话、数据库、日志不进入包，界面测试使用合成数据。Electron 官方下载不通时，可按其文档设置下载镜像，校验和仍需通过。

实现位置：`src/collector.ts` 采集状态机；`src/store.ts` SQLite 事务和增量记录；`src/transport.ts` 请求及结构校验；`src/browser.ts` 隔离的抖音网页容器；`public/renderer.js` 原页面功能；`src/tests` 逻辑与恢复测试。
